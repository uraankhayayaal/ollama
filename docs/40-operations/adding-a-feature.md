# Добавление новой фичи

## Чеклист

### 1. Определить слой

| Что добавляем | Слой | Где |
|---|---|---|
| Новый инструмент модели | `tools/` | `tools/registry.go:105` + реализация |
| Новое поведение агента | `agents/<роль>/` | промпт + `tools.Select` |
| Новый REST-эндпоинт | `server/` | `mux.HandleFunc` + хендлер |
| Новый источник данных | `runner/`, `board/`, `rag/` | интерфейс + реализация |
| Новый провайдер | `models/` | интерфейс + `ResolveProvider` |
| Новый фордж | `forges/` | реализация + саморегистрация в `init` |
| Новый стек | `stackdetect/`, `tools/stacktool.go` | детектор + роли |

### 2. Реализовать

Обязательные правила:

| Правило | Почему |
|---|---|
| Отсутствие внешнего сервиса → `skipped`, не `error` | Система обязана деградировать, а не падать |
| Значение по умолчанию при разборе env | Пустое значение не должно ломать поведение |
| Мутации файлов — под `filelock` | Параллельные шаги волны не рвут общие файлы |
| Не добавлять зависимость от `server` в `tools` | Иначе цикл импортов |
| Читать env **константой** рядом с местом чтения | `const reindexOnEnv = "RAG_AUTO_REINDEX"` |

### 3. Покрыть тестом

```bash
go test ./<пакет>/ -run TestNewFeature
```

Тест обязан покрывать **и деградацию** (сервис недоступен → `skipped`).
Подробнее — [Тестирование](testing.md).

### 4. Проверить

```bash
go build . ./agents/... ./tools/ ./board/
go vet   . ./agents/... ./tools/ ./board/
go test  . ./agents/... ./tools/ ./board/
gofmt -l <файлы-которые-вы-трогали>   # не `gofmt -l .`: см. ниже
```

> В репозитории 29 файлов с предсуществующими отклонениями форматирования,
> поэтому `gofmt -l .` всегда непустой. Форматируйте только свои файлы —
> иначе diff раздуется чужими правками.

Если затронут фронтенд:

```bash
npm --prefix web run build
```

## Обновление документации

Документация обязана оставаться в состоянии «факты из кода». Правило одно:
**новый код без нового (или обновлённого) документа — незавершённая работа.**

### Что обновлять

| Изменение | Документ |
|---|---|
| Новый инструмент | [Справочник инструментов](../30-reference/agent-tools.md), [Инструменты](../20-features/tools.md) |
| Новая env-переменная | [Справочник env](../30-reference/environment-variables.md) **и** доменный документ |
| Новый REST-маршрут | [REST API](../30-reference/rest-api.md) |
| Новое событие WebSocket | [REST API](../30-reference/rest-api.md), [Web UI](../20-features/web-ui.md) |
| Новая CLI-команда | [CLI](../30-reference/cli.md) |
| Новый порт или сервис | [Инфраструктура](../30-reference/infrastructure.md) |
| Новый домен | `docs/20-features/<домен>.md` + строка в [оглавлении фич](../20-features/README.md) |
| Новый шаг плана | [Планировщик](../20-features/planner.md) |
| Новый фазовый флаг | [Сжатие контекста](../20-features/context-compression.md) |

### Как писать доменный документ

Единая структура:

1. `# Заголовок` — что это в одном предложении.
2. `## Настройка` — только управляющие переменные, с дефолтами.
3. `## Как это работает` — механика, с ссылками `файл.go:строка`.
4. Таблицы поведения, режимов, кодов ответа.
5. Деградация — что будет, если сервис недоступен.
6. `## Проверить` — команды, которые это подтверждают.
7. `## Связанное` — 4-6 ссылок на смежные домены.

### Правила содержания

| Правило | Пример |
|---|---|
| Значение по умолчанию — **из кода** | `LSP_MAX_DIAGS=30` (`tools/lspcheck.go:75`) |
| Расхождение с `.env.example` — отметить явно | блок «Расхождение с ранними планами» |
| Ссылка на код — `путь/файл.go:строка` | `runner/compress.go:45` |
| Не дублировать справочник env | «настройка» здесь, «таблица» в `30-reference` |
| Писать по-русски | — |
| Не выдумывать поведение | если не проверил — не пиши |

### Куда что идёт

```
docs/
├── README.md                      ← оглавление: обновить при новом домене
├── 00-overview/                   ← изменилась архитектура?
├── 10-getting-started/            ← изменился запуск?
├── 20-features/<домен>.md         ← изменился домен
├── 30-reference/                  ← новые факты, которые нужны точно
└── 40-operations/                 ← изменился процесс разработки
```

### Проверка ссылок

После правок:

```bash
# Все Markdown-ссылки ведут в существующие файлы
grep -rho '](\.\.\?[^)#]*\.md' docs/ | sed 's/](//' | sort -u
```

Для каждого пути проверить `test -f`. Битые ссылки — недопустимы.

### Планы

Архивные планы лежат в `docs/plans/` и **не редактируются** — это история.
Новый план создаётся там же, но текущая документация обновляется по коду, а
не по плану.

Подробнее — [Планы реализации](../plans/README.md).
