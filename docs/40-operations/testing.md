# Тестирование

## Запуск

```bash
go test . ./agents/... ./tools/ ./board/          # рабочий набор
go test ./rag/ ./runner/ ./server/ ./workspace/   # расширенный
go test -race ./agents/... ./tools/               # с гонками
go test -run TestName ./tools/                    # один тест
go test -cover ./tools/                           # покрытие
```

Фронтенд:

```bash
npm --prefix web run typecheck
npm --prefix web run build
```

> У `web/` **нет** тестов: в `package.json` только `dev`, `build`, `preview`,
> `typecheck`. Проверка фронтенда — это `tsc` плюс успешная сборка.
> Тесты для генерируемых проектов (`pytest -q`, `npm test`) — это цикл
> приёмки в `agents/acceptor/`, а не тесты самого приложения.

## Герметичные тесты

Внешние сервисы в тестах **не используются** — вместо них подмены:

| Что | Чем заменено |
|---|---|
| Qdrant | `rag/memstore_test.go` — in-memory `QdrantStore` с семантикой фильтров (must/must_not/should, match, is_null, is_empty, has_id) |
| Модель эмбеддингов | `textEmbedder` |
| Git | инъектируемый `rag.gitRunner`, `gitops.Executor` |
| RAG-клиент сервера | фабрика `buildProjectIndexer` |
| Shell | `sandboxConfig.LocalCommand` (заглушка, чтобы тесты не дёргали shell) |

> `LocalCommand` в продакшне всегда `nil` (тогда `exec.Command`) — в тестах
> подменяется. Это единственный способ, которым тесты остаются hermetic.

## Живой E2E (опционально, нужна Ollama)

Правило «тесты не трогают внешние сервисы» действует для рабочего набора.
Один тест намеренно вынесен за build-тег `e2e` и в него не входит:

```bash
E2E_LIVE=1 go test -tags e2e -run TestE2EModelSelection ./server/ -timeout 10m
```

Что проверяет (`server/e2e_model_selection_test.go`) — полный путь «переключил
модель в Web UI → работает выбранная модель»:

| Шаг | Доказательство |
|---|---|
| Старт | `GET /api/providers` отдаёт выбор из окружения, провайдеры отсортированы |
| Переключение | `POST /api/providers/select` → `GET` показывает новую модель (регресс кэша провайдера) |
| Реальный чат | запрос к `/api/projects/{id}/chat` доходит до модели |
| Модель именно та | `/api/ps` Ollama: до запроса модели выгружены, поэтому загружена ровно выбранная |
| Логи | `server: LLM: …` в `server.log` и `[llm] модель: …` в логе проекта |
| Отказы | неизвестная модель/провайдер → 400, битый `base_url` → 400 + ошибка в `GET` |
| Сброс | `reset` возвращает выбор из окружения, `override=false` |

Доска в тесте — miniredis, как в остальных тестах `server/`: живой нужен только
Ollama. Модели подбираются автоматически из `/api/tags` (нужны две, умеющие
tool-calls — на них проверяется, что чат пошёл именно в выбранную модель).
Явно: `E2E_MODEL_SMALL`, `E2E_MODEL_SECOND`, `E2E_MODEL_LARGE`; адрес —
`OLLAMA_BASE_URL` (по умолчанию `http://127.0.0.1:11434`).

Без `E2E_LIVE=1` тест пропускается; без Ollama — тоже.

## Тесты, которые ловят реальные дефекты

Недавние находки — иллюстрация ценности in-memory Qdrant:

1. `IndexProject` искал исчезнувшие файлы по **ключам** карты `chunk_id`
   вместо значений — файлы не устаревали.
2. `activeBranchCond` для `main` строил взаимоисключающие `Must: branch=main`
   + `Should: is_null(branch)` — поиск из `main` не возвращал **ничего**.
3. `SetPayload` без `Wait` — гонка с prune и поиском.
4. Идемпотентность по одному `commit_sha` теряла незакоммиченные правки.
5. Флак тест-хелпера: `chunk_id` делится версиями одной функции **между
   ветками**, поэтому искать активную точку надо по `(branch, chunk_id)`;
   `codeOf` без ветки зависел от порядка обхода map.

## Известные падения

Ниже — то, что падает **на чистом HEAD** и не связано с текущей работой.
Проверяйте регрессию сравнением с чистым HEAD: если тест падает и там —
это не ваша правка.

### Зависит от хоста (проверено на macOS, GNU Make 3.81)

| Тест | Что ожидает | Что получает |
|---|---|---|
| `TestAcceptBuildFallsBackToInfraMirror` | повтор через `make infra.build` | `make build` — make-специфичный маркер не распознан |
| `TestAcceptBuildToolMissingSkips` | `Skipped: true` | `OK: false`, `make: *** [build] Error 1` |

Оба ждут make-маркер (`Ошибка` / `Error 127`), которого на хосте нет: локальный
`make` выполняет цель и возвращает `Error 1` с `No such file or
directory`. В контейнере приёмки зеркало `make infra.<цель>` работает.

### Флаки чат-ассистента

- `TestChatAssistantCreatesBugAndTask`
- `TestChatAssistantDeleteTaskAfterConfirm`
- `TestChatAssistantPublishesBoardWhenIdle`

Периодически падают по таймингу оркестрации; в последнем прогоне
`./agents/chatassist/` — зелёный.

## Правила написания тестов

| Правило | Зачем |
|---|---|
| Не использовать внешние сервисы | Тесты должны идти в CI без Docker |
| Детерминированный порядок обхода map | Порядок в Go случаен — сортируйте |
| Проверять оба пути: с сервисом и без | Деградация — часть контракта |
| Тест на границу лимита | Обрезка вывода, лимиты чанков |
| Комментарий в тесте — почему, а не что | Поясняет намерение |

## Проверить перед коммитом

```bash
go build . ./agents/... ./tools/ ./board/
go vet   . ./agents/... ./tools/ ./board/
go test  . ./agents/... ./tools/ ./board/
npm --prefix web run build
```

> `gofmt -l` сейчас **не является гейтом**: в репозитории 29 файлов с
> предсуществующими отклонениями форматирования (от отсутствующей
> завершающей строки до реальных перестановок в тестах). Форматируйте
> **только свои** файлы и не включайте чужие правки форматирования в коммит:
> `gofmt -l <ваш-файл>`.
