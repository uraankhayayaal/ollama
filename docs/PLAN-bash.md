# План: токено-эффективные Bash-команды агентов

Статус: **ПЛАН (реализация позже)**. Источник идей — `docs/PLAN-brainstorm.md`.
Обновлять файл по мере выполнения этапов (чекбоксы), как в `PLAN-webui.md`.

## Цель

Внедрить токено-эффективные паттерны работы с Bash, чтобы агенты не «съедали»
контекстное окно (`cat`, `grep -r`, полный вывод сборок). Аналогично LSP-плану:
гигиена чтения, а не новые возможности.

## Ключевые решения пользователя

1. **Не внедрять команды, дублирующие LSP/структурированные инструменты.**
   Разграничение зон:

   > LSP (LspDefinition/LspReferences/LspHover) и структурированные инструменты
   > (List/ReadMap/ReadFiles lines) — первичны для поиска символов и чтения кода.
   > Bash применяется только там, где LSP недоступен или у команды нет аналога:
   > git-контекст, компактный вывод проверок, grep-фолбэк при `status skipped`.

2. **Две разные аудитории правил:**
   - **Внутренние агенты** (`agents/*`): Bash-инструмента нет, есть только `Run`
     (`tools/fileops.go:894`, `runCommand`). Внедряются только непересекающиеся
     команды + правила компактного вывода.
   - **opencode/CLI-агенты** (этот репозиторий, `AGENTS.md`): Bash реально
     используется напрямую — внедряется весь список, но с приоритетами.

## Анализ команд из брейншторма (что внедряем)

| # | Команда из брейншторма | Решение | Причина |
|---|---|---|---|
| 1 | `find . -maxdepth 3` (структура) | **(не внедрять)** внутр. агентам; опционально в AGENTS.md | Дублирует `List`/`ReadMap` |
| 2 | `grep -rnw --exclude-dir` (поиск) | **фолбэк LSP**: только при `status skipped` / стек без LSP; в AGENTS.md — внедрять | Дублирует `LspDefinition`/`LspReferences`, но нужен как дешёвый запасной путь |
| 3 | `sed -n '1,50p'` / `head` (сигнатуры) | **(не внедрять)** внутр. агентам; опционально в AGENTS.md | Дублирует `ReadMap`/`LspHover`/`ReadFiles lines` |
| 4 | python AST — листинг функций | **(не внедрять как команду)**; возможно программный инструмент (см. Ф-4) | Аналог `ReadMap`/LspHover; в AGENTS.md — опционально |
| 5 | `git log -n 3 --oneline` / `git blame -L` | **внедрять** | Уникальный контекст, аналога у LSP нет |
| 6 | `pytest -q` / `npm test -- --silent` | **внедрять** | Компактный вывод проверок, с LSP не пересекается |

**Явные запреты** (общие для обеих аудиторий):
- Не использовать `cat`/`head`/`tail`/`grep -r` «в лоб» для чтения файлов — вместо
  этого структурированные инструменты или компактные флаги.
- Вывод сборок/тестов фильтровать (`-q`, `--silent`, `gofmt -l` без `-d`).
