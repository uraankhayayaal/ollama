# Быстрый старт

От чистой машины до первого сгенерированного проекта.

## 0. Требования

| Что | Минимум | Зачем |
|---|---|---|
| Go | 1.26.5 | Сборка |
| Docker | любой актуальный | Redis, Qdrant, образы песочницы |
| Ollama (или YandexGPT/Trim) | — | Модели |
| ОЗУ | 16 ГБ (с локальной 8B-моделью) | Модель целиком в памяти |

Подробнее — [Установка и инфраструктура](installation.md).

## 1. Поднять инфраструктуру

```bash
docker compose up -d
```

Поднимаются два сервиса: **Qdrant** (gRPC `56334`) и **Redis** (`56379`).
Подробнее — [Инфраструктура](../30-reference/infrastructure.md).

## 2. Поднять Ollama (если используете локальные модели)

> `compose.yaml` поднимает **только** Qdrant и Redis — сервиса `ollama` в
> нём нет. Ollama ставится отдельно.

```bash
# macOS
brew install ollama && ollama serve

# Linux — официальный установщик
curl -fsSL https://ollama.com/install.sh | sh
```

Либо используйте облачного провайдера — тогда Ollama не нужна. См.
[LLM-провайдеры](providers.md).

## 3. Скачать модель

```bash
ollama pull qwen3-coder:30b   # рядовые шаги
ollama pull qwen3:8b          # быстрые запросы
```

## 4. Настроить `.env`

```bash
cp .env.example .env
```

Минимально обязательное:

```bash
LLM_PROVIDER=ollama
OLLAMA_MODEL=qwen3-coder:30b
# OLLAMA_MODEL_LARGE=...   # для лидов, архитектора, ревьюера
```

`LLM_PROVIDER` — единственная по-настоящему обязательная переменная: без неё
запуск падает с «unknown provider» (`models/resolve.go:24,57`).

Подробнее — [Конфигурация](configuration.md).

## 5. Выбрать режим работы

| Что хочется | Команда |
|---|---|
| Сгенерировать бэкенд с нуля | `go run . backend storageService "Напиши микросервис хранения файлов"` |
| Сгенерировать фронтенд | `go run . frontend storageService "Веб-интерфейс для просмотра файлов"` |
| Спланировать и выполнить задачу по шагам | `go run . plan storageService "Создай микросервис и автотесты"` |
| Полная оркестрация через доску | `go run . kanban storageService "Опиши систему заметок"` |
| Проверить уже собранный проект | `go run . accept storageService` |
| Всё через браузер | `go run . serve` → http://127.0.0.1:8090 |

Проекты создаются в `temp/<имя_проекта>/` — имя проекта обязательный первый
аргумент, промпт можно опустить (тогда возьмётся задание по умолчанию).

Полный список команд — [CLI](../30-reference/cli.md).

## 6. Web UI (рекомендуемый режим)

```bash
npm --prefix web install     # один раз
npm --prefix web run build   # пересобрать фронтенд после изменений
go run . serve
```

Открыть http://127.0.0.1:8090.

- **Добавить проект** — кнопка в шапке, путь к каталогу (`temp/<имя>` или
  существующий git-репозиторий).
- **Запустить оркестрацию** — написать задачу в чат. Ассистент создаст эпик,
  лиды разложат его в задачи, специалисты выполнят.
- **Смотреть прогресс** — доска слева, чат по центру, диффы и логи справа.

Защита входа включается `AI_WEB_PASSWORD` (пусто — выключена).

Подробнее — [Web UI](../20-features/web-ui.md).

## 7. Построить RAG-индекс (опционально)

Семантический поиск по коду заметно ускоряет работу агентов на больших
проектах:

```bash
go run . index storageService
```

Требует поднятый Qdrant. Без него `CodeSearch` просто возвращает
`skipped` — остальная система работает.

Подробнее — [RAG и CodeSearch](../20-features/rag.md).

## 8. Разработка фронтенда

```bash
npm --prefix web run dev       # vite на :5173, проксирует /api на :8090
```

## Проверить, что всё работает

```bash
go build . ./agents/... ./tools/ ./board/   # сборка
go vet . ./agents/... ./tools/ ./board/     # статический анализ
go test . ./agents/... ./tools/ ./board/    # тесты
```

> `go build ./...` падает на артефактах в `temp/` (сгенерированные проекты) —
> используйте перечень выше. Подробнее —
> [Тестирование](../40-operations/testing.md).
