# Код-ревью Merge Request

Ревью MR с публикацией замечаний, блокировкой апрува при критичных
находках и ревью больших диффов по частям.

```bash
go run . review <URL_MR>
```

Поддерживаются GitLab и GitHub (через `forges/`).

## Настройка

```bash
# Доступ
GITHUB_TOKEN=...                # scope: repo (или public_repo для публичных)
GITLAB_TOKEN=...                # scope: api, read_api
GITLAB_URL=...                  # адрес GitLab без завершающего слэша

# Поведение
REVIEW_MAX_COMMENTS=10          # лимит замечаний за ревью (0 = без лимита)
REVIEW_CRITICAL_ONLY=1          # только критические (вкл по умолчанию)
REVIEW_BLOCK_ON_CRITICAL=1      # блокировать апрув при «критично:»
REVIEW_SKIP_GENERATED=1         # отсекать сгенерированные/бинарные файлы
REVIEW_MAX_ROUNDS=3             # раундов модель→инструменты за ревью
REVIEW_FIX_ROUNDS=3             # циклов «ревью → исправление → ревью» в планировщике

# Размеры
REVIEW_MAX_DIFF_SIZE=300000     # порог обрезания диффа, байты
REVIEW_CHUNK_SIZE=14000         # размер части для ревью по частям (0 = без)
REVIEW_TIMEOUT=10m              # таймаут всего цикла агента
```

Значения по умолчанию — `agents/codereviewer/config.go:43-52`.

> **Расхождение с ранними планами:** там указывалось
> `REVIEW_MAX_ROUNDS=12`. По умолчанию в коде **3**
> (`agents/codereviewer/config.go:48`). Если нужен длинный разбор —
> задайте явно, ревью по частям действительно требует больше раундов.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `ReviewMr` | Получить дифф MR, опубликовать замечания |
| `ApproveMr` | Апрув (блокируется при критичных замечаниях) |
| `NextChunk` | Взять следующую часть большого диффа |

`ReviewMr`/`ApproveMr` делят состояние цикла через `*ReviewSession`
(`tools/reviewsession.go`), чтобы ревью по частям накапливало общий
результат.

## Как проходит ревью

```
Загрузка MR (фордж: gitlab/github/local)
      │
      ▼
DiffFilter — отсечение сгенерированных/бинарных (REVIEW_SKIP_GENERATED)
      │
      ▼
Проверка размера (REVIEW_MAX_DIFF_SIZE)
   превышен → обрезание + примечание в ответе ревьювера
      │
      ▼
Разбиение на части (REVIEW_CHUNK_SIZE)
   0 → без разбиения, дифф целиком
      │
      ▼
Цикл раундов (REVIEW_MAX_ROUNDS)
   модель ←→ ReviewMr / NextChunk
      │
      ▼
Фильтрация замечаний
   REVIEW_CRITICAL_ONLY → только «критично»
      │
      ▼
REVIEW_MAX_COMMENTS — обрезка списка
      │
      ▼
ApproveMr
   блокируется, если есть критичные и REVIEW_BLOCK_ON_CRITICAL
```

## Критичность

Замечание считается критичным по префиксу `критично:` в тексте. Ревьюер
обучен классифицировать: баги, падения, уязвимости, гонки, утечки ресурсов.
Стиль и «можно лучше» отсекаются при `REVIEW_CRITICAL_ONLY`.

## Большие диффы

`REVIEW_CHUNK_SIZE` (символов) — с какого размера дифф ревьюится по частям.
Это снижает и переполнение контекста, и галлюцинации. `NextChunk` выдаёт
следующую часть.

`REVIEW_MAX_DIFF_SIZE` (байт) — порог, с которого дифф начинает
обрезаться. При превышении в ответ ревьювера добавляется примечание об
обрезании, чтобы он не считал результат полным.

**Особенность Trim:** `noChunk` — дифф передаётся целиком, без разбиения.
На Trim стоит держать `REVIEW_MAX_DIFF_SIZE` небольшим.

## Цикл исправления в планировщике

`REVIEW_FIX_ROUNDS` (по умолчанию 3) — замечания ревью превращаются в
шаги `refactor`, затем ревью повторяется. `1` = один проход без цикла
исправлений.

## Слушатель новых MR

```bash
go run . listen
GITLAB_URL=...
GITLAB_PROJECTS=123,456         # ID проектов через запятую
DB_FILENAME=discovered_mrs.txt  # файл-база уже известных MR
POLL_INTERVAL=30s
```

`services/mrlistener` — периодический опрос новых MR. База известных MR
хранится в файле, поэтому повторно один и тот же MR не ревьюится.

> Слушатель работает **только с GitLab** — по `GITLAB_URL` + `GITLAB_PROJECTS`.
> Вебхуков нет.

## Форджи

| Фордж | Требования | Назначение |
|---|---|---|
| `gitlab` | `GITLAB_TOKEN`, `GITLAB_URL` | Ревью, комментарии, создание MR |
| `github` | `GITHUB_TOKEN` | То же для GitHub |
| `local` | — | Локальный git без форджа (только чтение) |

Реестр с саморегистрацией через `init` (`forges/registry.go:13-36`).
Интерфейс `Forge` — `forges/forges.go:20-35`.

## Определение языка

`langdetect/` — 21 язык, карта расширений, `Detect(diff)` по заголовкам
`+++`. При равенстве кандидатов выбор детерминирован
(`langdetect.go:137-147`). Язык влияет на промпт ревьюера.
