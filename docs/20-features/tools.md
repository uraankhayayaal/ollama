# Инструменты агентов

Function calling: модель возвращает JSON-вызов, раннер диспетчеризует его по
имени. Набор инструментов агента собирается через `tools.Select(names, deps)`.

## Как это устроено

| Понятие | Что это |
|---|---|
| `tools.Tool` | Интерфейс инструмента: описание для провайдера + `Execute` |
| `tools.Deps` | Общий контекст: `FileOps`, `Session`, `Board`, `RAG`, `GitExec` |
| `tools.Set` | Набор конкретного агента: `Get`, `Has`, `Execute`, `Add` |
| `newTool` | Фабрика реестра: имя → реализация (`tools/registry.go:105-190`) |
| `boardConnected` | Различает «доска не подключена» (мягкая ошибка) и «инструмент не выдан» (жёсткая) |

**Важно:** `Board*` не выдаются вообще, если `deps.Board == nil`
(`registry.go:34-36`). Это автоматическая деградация standalone-агентов.

Серверные мосты (`AskUser`, `IndexBackground`, `KanbanStart`, `TaskMerge`,
`EpicRelease`, `BranchReject`) добавляются через `Set.Add` — объявить их в
реестре `tools` нельзя из-за цикла импортов.

## Файловые операции

| Инструмент | Что делает | Ключевые параметры |
|---|---|---|
| `WriteFiles` | Записать несколько файлов | `files[]` |
| `ReadFiles` | Прочитать файлы | `files[]`, `lines` (окно строк) |
| `ReadMap` | Карта проекта: путь, размер, язык | — |
| `List` | Дерево файлов с фильтром по scope | — |
| `DeleteFiles` | Удалить файлы | `files[]` |
| `AppendFile` | Дописать в конец | `path`, `content` |
| `Run` | Выполнить команду | `command` |

### Лимиты чтения

```bash
CODEGEN_READ_MAX_FILE=100000    # верхняя граница символов на файл
CODEGEN_READ_CHUNK=16384        # порция чтения на файл за вызов
CODEGEN_READ_MAX_FILES=3        # файлов за вызов
CODEGEN_READ_MAX_TOTAL=800000   # символов за вызов ReadFiles
```

Действующая порция на файл = `min(CODEGEN_READ_CHUNK, CODEGEN_READ_MAX_FILE)`.

**Пагинация вместо молчаливой обрезки.** Файл больше порции не усекается
«за спиной» модели: запись ответа получает `has_more: true` и `next_offset`,
а `message` прямо просит вызвать `ReadFiles` снова с `offset=<next_offset>`.
Раньше хвост файла просто исчезал, агент видел только начало и уходил в
цикл перечитываний. Порции выровнены по границам UTF-8, поэтому символ
не разрезается границей, а `offset` внутри символа отклоняется с подсказкой
вместо молчаливой подмены байтов на `U+FFFD` (которую делает `json.Marshal`).

**Мягкий лимит на число файлов.** За один вызов читаются первые
`CODEGEN_READ_MAX_FILES` файлов; остальные получают `status: "skipped"` с
подсказкой заказать их отдельным вызовом. Вызов не падает — модель видит,
что запрос не потерян. Модель склонна заказывать 8-14 файлов разом, и
остальные уходили «под нож», провоцируя повторные перечитывания.

Бинарные файлы (NUL-байт в порции) отклоняются: сырые байты в контексте
бессмысленны и ломают разбор.

При превышении суммарного лимита файлы читаются **по убыванию приоритета**
(`main.go`, `payload.before`, `small.snippet`), остальные — только имена.

`ReadFiles` поддерживает «хирургическое окно» по строкам
(`lines: "20-45"`) — чтение части файла вместо целого. `lines` и `offset`
взаимоисключающи: при заданном `lines` `offset` игнорируется.

### Лимиты выполнения

```bash
CODEGEN_RUN_TIMEOUT=60s
CODEGEN_RUN_MAX_OUTPUT=20000
```

Долгоживущие команды (`npm run dev`, сервер) прерываются по таймауту с
понятной ошибкой, а не висят. Вывод обрезается до `CODEGEN_RUN_MAX_OUTPUT`
(`fileops.go:661-688`).

`Run` выполняется на хосте или в песочнице — см. [Песочница](sandbox.md).

### Скоупы и блокировки

`List` фильтрует по `ops.allowed` (`fileops.go:890-913`) — агент видит
только свою область.

Все мутации (`Write`, `AppendTo`, `Remove`, `SearchReplace`,
`PatchGoFunction`, `snapshot.Restore`) выполняются под **пер-проектной
блокировкой** (`tools/filelock.go`): параллельные шаги волны не рвут
общие файлы. Разные проекты и тесты не блокируют друг друга.

### Stub-healing

Если на пути каталога оказался 0-байтовый файл-заглушка, инструменты
автоматически его лечат (удаляют и создают каталог). **Непустой** файл на
пути каталога — ошибка, он не трогается.

Родительские каталоги создаются автоматически при записи.

## Точечные правки

| Инструмент | Что делает |
|---|---|
| `SearchReplace` | Универсальные блоки `<<<<<<< SEARCH ... ======= ... >>>>>>> REPLACE`. Дословное совпадение искомого фрагмента; при промахе файл **не изменяется** |
| `PatchGoFunction` | Семантическая замена одной Go-функции через `go/ast`, форматирование через `go/format`, опциональное добавление импортов |
| `PatchFunction` | То же для других языков |

Механизм изолирует правку субагента: он не переписывает и не удаляет
функционал, реализованный другими задачами плана.

## Параллельные вызовы

Read-only инструменты одного раунда выполняются **параллельно по умолчанию**
(`runner/runner.go:409-427`). Ширина волны — `PARALLEL_TOOL_MAX` (8),
`0` = без ограничения. Выключается `PARALLEL_TOOL_CALLS=0`.

Параллельно безопасны только read-only инструменты (`tools.IsParallelSafe`):
все мутации — строго последовательно, в порядке вызова, и дополнительно
сериализуются `filelock`.

## Сбойные вызовы

Если модель обрывает JSON аргументов (llama-server иногда не дочитывает
вывод), провайдер делает авто-ретрай: `OLLAMA_TOOL_RETRIES` (по умолчанию 2),
пауза `OLLAMA_TOOL_RETRY_DELAY` (1000 мс).

## Формат ответа

Инструменты возвращают структурированный результат с полем `status`:

| `status` | Значение |
|---|---|
| `success` | Выполнено |
| `skipped` | Не применимо (нет сервера, нет проекта, внешний сервис недоступен) |
| `error` | Ошибка выполнения |
| `confirm` | Требуется подтверждение пользователя (серверные мосты) |

`skipped` — не ошибка: агент получает подсказку и продолжает.

## Как добавить инструмент

1. Реализовать интерфейс `tools.Tool` (или использовать готовую обёртку).
2. Добавить имя в `newTool` (`tools/registry.go:105`).
3. Добавить константу имени, если инструмент используется как строка.
4. Выдать инструмент агенту в его `tools.Select([...])`.
5. Покрыть тестом (паттерн `tools/*_test.go`).
6. Обновить [эту таблицу](../30-reference/agent-tools.md) и документацию по
   [чеклисту](../40-operations/adding-a-feature.md).
