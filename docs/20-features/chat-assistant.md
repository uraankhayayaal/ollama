# Чат-ассистент

Агент, обслуживающий чат Web UI: понимает намерения по смыслу, отвечает по
проекту, создаёт эпики, задаёт уточняющие вопросы, выполняет git-операции.

Работает **только** в Web UI (`serve`). Отдельной CLI-команды нет.

## Настройка

```bash
RAG_ASSISTANT_CONTEXT=1    # RAG-контекст ассистента (вкл по умолчанию)
```

> Флага нет в `.env.example`, но он активен по умолчанию
> (`agents/chatassist/ragcontext.go:84-91`). Выключается `0`/`false`/`off`/`no`.

## Поток обработки

`server/chatassist.go:32-94`:

```
Сообщение пользователя
      │
      ▼
runChatAssistant (отдельная горутина)
      │
      ├── Работает в Root зарегистрированного проекта
      ├── Ленивый RAG-клиент
      ├── История диалога: последние 12 реплик, до 400 символов
      ├── Мосты: serverActionTools
      └── Репортер через runevents + runctx.WithCompression
      │
      ▼
Модель решает: ответить / создать эпик / выполнить действие / спросить
      │
      ▼
Ответ в чат (пустой финал заменяется уточняющим вопросом, :83-86)
```

**Бинарный сплит по ключевым словам убран** — триггером служит вызов
инструмента моделью, а не разбор текста.

## Что попадает в промпт

`server/chatassist.go:287-414`:

- Вопрос пользователя.
- **«Якорь действия»** (`chatActionAnchor:196-251`) — защита от цикла
  переспросов.
- Состояние оркестрации: `running` / `gating` / `idle`.
- **Ревизия доски: N** (счётчик `boardRev`) — чтобы ассистент понимал, что
  доска изменилась не по его инициативе.
- Исходное ТЗ из `Meta`.
- Эпики и сводка задач по статусам (включая `paused`).
- Список задач «в работе».
- **Блок конфликтов мёрджа** (`:372-395`).
- Баги по статусам.

## Правила поведения

`agents/chatassist/agent.go`:

| Правило | Содержание |
|---|---|
| Маршрутизация | «завести» / «запланировать» → `BoardCreateEpic`; «сделать сейчас» → `KanbanStart` |
| Подтверждение | Создание записи — **без** подтверждения (`:59`) |
| Черновик | Эпик из чата — черновик; `assigned_role` **не выдумывать** (`:61`) |
| Деструктивность | Удаление эпика, `cancelled`, `TaskMerge`, `EpicRelease`, `BranchReject`, `EpicResolve` — только после явного «да» (`:70`) |
| Антизацикливание | Счётчик `seenCalls` запрещает повтор одного и того же инструмента (`:68`); общий детектор петли в `runner/loop.go` — [разрыв петли](agents-and-roles.md#разрыв-петли) |
| Конфликты | Конфликт эпика → `ResolveGitConflicts` (status/start/apply) → `EpicResolve`; конфликт задачи → сообщить и предложить путь (`:74-79`) |

> **Намеренное ограничение:** у ассистента нет инструментов
> `BoardCreateTask` / `BoardUpdateTask` / `BoardDeleteTask` (закреплено
> тестом `agents/chatassist/agent_test.go:99`). Задачи создаёт лид —
> иначе декомпозиция не согласована с архитектурой.

## Инструменты

21 инструмент:

- Чтение: `List`, `ReadFiles`, `LspDefinition`, `LspReferences`, `LspHover`.
- Поиск: `CodeSearch`, `WebSearch`.
- Доска (15): эпики Create/Update/Delete/SetStatus, `BoardSetTaskStatus`,

### Серверные мосты

Объявлены в `server/actions.go` — в реестре `tools` их быть не может
(цикл импортов), поэтому добавляются через `Set.Add`.

| Инструмент | Опасность | Что делает |
|---|---|---|
| `KanbanStart` | Безопасен | Запустить оркестрацию |
| `AskUser` | Безопасен | Задать структурированные вопросы |
| `IndexBackground` | Безопасен | Фоновая индексация RAG |
| `TaskMerge` | **Деструктивен** | Влить задачу в релизную ветку |
| `EpicRelease` | **Деструктивен** | Выпустить эпик |
| `BranchReject` | **Деструктивен** | Отклонить фича-ветку |
| `ResolveGitConflicts` (обвязка) | — | Разбор конфликтов |
| `ReadProjectLogs` | Безопасен | Прочитать сырые строки логов проекта |

Обёртка `actionTool.Execute` (`actions.go:115-131`): при отсутствии согласия
возвращает `status=confirm`, **не тратя раунд**. Слова подтверждения
(`confirmTokens:378-389`, включая `lf` — русское «да» в латинской
раскладке). `ActionConfirmed` смотрит последнее сообщение роли `user`
(`:362-374`).

## Вопросы пользователю (`AskUser`)

`server/ask.go`. Агент может задать пачку структурированных вопросов с
вариантами — UI показывает карточку `AskCard`.

Схема вопроса:

```json
{
  "id": "storage",
  "text": "Какое хранилище использовать?",
  "kind": "single",
  "allow_custom": true,
  "options": [
    {"id": "postgres", "label": "PostgreSQL", "recommended": true},
    {"id": "sqlite", "label": "SQLite"}
  ]
}
```

| Поле | По умолчанию |
|---|---|
| `kind` | `single` (или `multi`) |
| `allow_custom` | `true` |
| `options[].recommended` | — |

Поведение:

- Таймаут ожидания — **15 минут** (`ask.go:115`), затем `context.DeadlineExceeded`.
- Один активный вопрос на сессию; повторный вызов — ошибка (`:213-217`).
- Вопрос публикуется в чат как `role=ask` (`:229`).
- Ответы возвращаются в порядке вопросов (`:279-286`).
- Статус-строка суммирует ответы (`summarizeAsk:315`).

Ответ через REST:

```http
POST /api/projects/{id}/ask/{askID}/answer
```

Клиент: `answerAsk` (`web/src/Api/Api.ts:276`), UI:
`Components/Chatboard/AskCard`.

## Конфликты мёрджа в чате

Если `merge_conflict_files` не пусто, блок конфликтов попадает в промпт
ассистента. Дальше:

- **Конфликт задачи:** `TaskMerge` возвращает детерминированную строку со
  списком файлов и точкой резолва; состояние **не меняется**
  (`server/actions.go:288-299`). Ассистент сообщает пользователю и
  предлагает путь.
- **Конфликт эпика:** ассистент ведёт через `ResolveGitConflicts`
  (status → start → apply), затем `EpicResolve` снимает признак конфликта.

## Разбор логов (`log_analysis`)

Ход, порождённый кнопкой «Разобрать» в панели логов. Пользователь ничего не
писал, поэтому в историю **не добавляется выдуманная реплика** — только
служебная строка статуса «Разбор логов: <файл>».

`server/loganalysis.go` собирает разбор детерминированно: читает те же
файлы, что показывает Logboard (`collectProjectLogs`), применяет фильтры
поиска и минимальной тяжести к строкам **до** группировки, после чего
`buildLogDigest` (`server/logdigest.go`) сворачивает повторы в находки.
В промпт уходит дайджест (`=== РАЗБОР ЛОГА ПРОЕКТА ===`) с явным контрактом
ответа и указанием условий выборки — иначе модель делает выводы по
подмножеству как по всему логу.

Особенности, которые неочевидны:

- **Уровень берётся из собственного тега строки**, а не поиском слова:
  `DETAIL`-строки с `{"level":"ERROR"}` внутри аргументов инструментов иначе
  дали бы массу ложных находок. Эвристика уровня применяется только к
  нетегированным строкам (логи самого приложения пишутся его логгером).
- **Шаблонизация** (`<path>`, `<file>`, `<n>`, `<uuid>`, `<str>`) обязательна:
  без неё один и тот же сбой на тысяче строк даёт тысячу находок.
- **Кадры стека** приклеиваются к находке и переживают фильтр по уровню:
  иначе доказательство ошибки вырезается.
- **Пустой разбор** отвечает детерминированно, без вызова модели.
- **Cooldown 90 с** на неизменившийся лог: два клика подряд не зовут модель
  дважды.

Докапывание — инструментом `ReadProjectLogs` (`server/actions_logs.go`):
логи лежат в `logs/<проект>.log`, то есть **вне** корня рабочей папки,
куда файловые инструменты ассистента (`tools/fileops.go:ResolvePath`) не
пускают, — поэтому нужен серверный мост. Он отдаёт хвост файла (200 строк
по умолчанию, потолок 1000) с необязательным `grep`, и ровно те же файлы,
что видит Logboard: чужие логи проектов и `server.log` не утекают.

## Промпт-инъекции (injections)

Промпт-инъекции — структурированные фрагменты системных сообщений, которые
применяются к работе ассистента и оркестратора в реальном времени (runtime),
без перезапуска сервера.

### Источники (scope)

Инъекции собираются из четырёх источников в порядке `global → assistant
→ session → runtime` и применяются к каждому вызову модели (`runner/runner.go:583-613`,
функция `collectInjs` + `injections.ApplyInjections`):

| Scope | Источник | Применение |
|---|---|---|
| `global` | Конфиг приложения (`server.Config`) | Действует для **всех** сессий |
| `assistant` | Поле `Assistant.Injections` | Для **всех** вызовов этого ассистента |
| `session` | `Session.sessionInjections` + API | Только для текущей сессии (горячее применение) |
| `runtime` | `board.Task.Injections` + контекст задачи | Только для одной задачи |

### Структура инъекции

```json
{
  "id": "chat-rag-disable",
  "name": "disable-chat-rag",
  "scope": "session",
  "target": "system",
  "position": "prepend",
  "content": "⚠️ RAG-поиск отключён. Не вызывай CodeSearch.",
  "when": "model == \"llama3.1\"",
  "enabled": true,
  "priority": 10
}
```

| Поле | Описание | Возможные значения |
|---|---|---|
| `id` | Уникальный идентификатор (для удаления) | строка |
| `name` | Имя (обязательно) | — |
| `scope` | Источник (информативно) | `global`, `assistant`, `session`, `runtime` |
| `target` | Куда вставить | `system`, `messages`, `user_last`, `assistant_last` |
| `position` | Как вставить | `prepend`, `append`, `replace`, `inject_at_index` |
| `index` | Индекс (только для `inject_at_index`) | int |
| `content` | Тело инъекции (шаблон) | строка, до 10 KB |
| `when` | Условие (`when`-фильтр) | boolean expr: `==`, `!=`, `&&`, `\|\|`, `!` |
| `enabled` | Активна | True / False |
| `priority` | Приоритет (убывание) | int (по умолчанию 0) |
| `vars` | Переменные шаблона | map |
| `tags` | Метки | []string |

### API для сессионных инъекций

| Эндпоинт | Что делает |
|---|---|
| `POST /api/projects/{id}/injections` | Добавить инъекцию (JSON body) |
| `DELETE /api/projects/{id}/injections/{injID}` | Удалить по ID |
| `GET /api/projects/{id}/injections` | Список активных注入 |

**Пример добавления:**

```http
POST /api/projects/mytrip/injections
Content-Type: application/json

{
  "name": "禁用特定模型",
  "scope": "session",
  "target": "system",
  "position": "prepend",
  "content": "Модель <<"llama3">"可能会有幻觉。回答时保持谨慎。"
}
```

### Шаблонизация и условия

`content` поддерживает `$`-переменные: `{{vars.*}}, {{env.*}}, {{session.*}},
{{assistant.*}}`. Чувствительные переменные окружения (`*_TOKEN`, `*_SECRET`,
`*_KEY`)Redacted (заменяются на `[REDACTED]`).

Условие `when` — булево выражение с дискованными переменными: `model`,
`provider`, `role`, `project`, `turn`, `user`, `has_files`, `has_tools`.

### Ограничения

- `MaxContentSize` = 10 KB на инъекцию (обрезается + предупреждение).
- `MaxTotalSize` = 50 KB суммарно (остальные пропускаются).
- Fast-path: если никаких инъекций нет — промпт собирается без изменения
  (обратная совместимость с существующими ассистентами без `injections`).

### Диаграмма пайплайна

```
Global injections (config)
    ↓
Assistant injections (struct field)
    ↓
Session injections (API add)
    ↓
Runtime injections (task taskAssigned)
    ↓
ApplyInjections(ctx, context.mergeFn, ...) → applied → system + messages
```
