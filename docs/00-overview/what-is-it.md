# Что это за проект

Мультиагентная система автоматической разработки. По промпту пользователя
агенты проектируют, генерируют, собирают, тестируют и ревьюят приложения,
ведут Kanban-доску и работают с Merge Request'ами.

Код — Go (`module ai`), промпты, комментарии и логи — на русском. Фронтенд —
React + TypeScript, собирается в бинарь через `embed`.

## Главное в двух абзацах

Пользователь описывает задачу словами. Дальше работает **оркестрация**:
системный архитектор превращает её в эпики на Kanban-доске, лиды
декомпозируют эпики в атомарные задачи, специалисты выполняют задачи,
каждый закрывая свою задачу в доске, а приёмка детерминированно собирает,
запускает и проверяет проект. Ничего из этого не зависит от того, чтобы
человек вручную нажимал кнопки — вместо этого есть Web UI, где вместо
нажатий используются вопросы, ответы и решения об ошибках.

## Ключевые идеи

- **Весь проект — одним ответом модели.** Промпты требуют завершать задачу в
  одном ответе единым `WriteFiles`: меньше раундов — меньше потерь контекста.
- **Приёмка без LLM.** Сборка, запуск, чтение логов, `gofmt`/`vet` выполняются
  детерминированным кодом. Именно это защищает от «красивых, но не собирающихся»
  проектов. LLM подключается только для составления плана исправлений.
- **Контекст — конечный ресурс.** Скелетон-кеш, сжатие истории, вытеснение в
  RAG-эпизоды, семантическое ранжирование — всё это нужно, чтобы длинные
  сессии не падали с `exceed_context_size`.
- **Двухслойная маршрутизация моделей.** Рядовые шаги идут на лёгкую модель,
  лиды / архитектор / ревьюер и эскалации — на тяжёлую.
- **Изоляция по scope.** Каждый шаг работает в своей области файлов; перед
  шагом снимается scoped-снимок, чтобы откатить именно неудачный шаг, не
  задев соседние.
- **Индекс знает про Git.** RAG версионирован по веткам: агент в своей
  фича-ветке видит актуальный код этой ветки, а не main.

## Границы системы

Что система **не** делает:

- Не деплоит в продакшен — приёмка доводит до «собирается, запускается,
  логи чистые, тесты проходят».
- Не поддерживает вебхуки: новые MR обнаруживаются поллингом (`listen`).
- Не изолирует команды `Run` от файловых правок соседнего шага волны
  (осознанный компромисс: сборка дольше правок; строгий режим —
  `CODEGEN_PARALLEL=0`).
- Аудит публичного API реализован только для Go.
- Форджи ограничены GitLab и GitHub.
