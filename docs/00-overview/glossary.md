# Глоссарий

Термины, которые используются по всей документации и в коде.

## Задачи и доска

**Эпик** — крупная единица работы верхнего уровня. Создаёт системный
архитектор. Публикуется на доску и раскладывается лидами в задачи.
Соответствует релизной ветке `ai/epic/<id>`.
См. [Kanban-доска](../20-features/kanban-board.md).

**Задача** — атомарная единица работы, которую выполняет один специалист.
Создаёт лид направления. Соответствует фича-ветке `ai/task/<id>`.

**Багрепорт** — зарегистрированная проблема. Создаёт QA-инженер или приёмка.
Проходит триаж (`confirmed`/`slop`), затем вердикт архитектора-эксперта
(`fix`/`feature`/`wont_fix`).

**Opportunity** — кросс-функциональная рекомендация: «эта задача создаёт
работу для смежной роли». Поле `opportunities[]` в бэклоге архитектора
(`board/entity.go:149-162`).

**Черновик эпика** — эпик с `requires_review=true`. Создаётся архитектором
(`BoardCreateEpic` всегда ставит `true`, `tools/board_tools.go:411`) и ждёт
ревизии. Важно: **отсутствующее поле `requires_review` при разборе JSON
трактуется как `true`** (`board/entity.go:290-306`) — это защитный дефолт,
из-за которого старые записи требуют ревизии.

**LeadSyncedRev** — ревизия эпика, под которую лид уже видел задачи.
Выравнивается после ревизии, чтобы лид не принял эпик заново
(`kanban.go:733-739`).

## Планирование и исполнение

**Скоуп (scope)** — область работы шага или задачи: конкретные файлы и
каталоги. Агент работает только в своём скоупе. Снимок скоупа снимается
перед шагом — по нему делается откат.

**Волна (wave)** — группа шагов без зависимостей между собой, которые можно
выполнить параллельно. Волны выполняются строго последовательно, шаги внутри
волны — параллельно (`agents/planner/executor.go:157-163`).

**Откат (rollback)** — восстановление скоупа до состояния перед шагом.
Включён по умолчанию (`CODEGEN_ROLLBACK_ON_FAIL`). Не выполняется при
исчерпании лимита раундов — иначе сломался бы resume.

**Resume** — продолжение прерванного плана с последнего незавершённого шага
(`plan --resume` / `PLAN_RESUME=1`). Планировщик при resume не вызывается.

**Чекпоинт** — снимок состояния плана в Redis: статусы шагов
(`pending`/`running`/`done`/`failed`/`skipped`) и метрики.

**Контракт публичного API** — снимок экспортируемых сущностей Go-пакета,
снимаемый между шагами. Необъявленное изменение видно как `+/-/~`.
Реализован только для Go.

**Карта проекта** — компактное описание структуры (файлы, размеры, языки,
без содержимого), которое подсказывает планировщику разбиение
(`agents/planner/project_map.go`).

## Агенты

**Архитектор** — верхний уровень проектирования, публикует эпики.
Работает в трёх режимах: базовый, `AsReviewer()` (ревизия черновиков),
`AsBugExpert()` (вердикты по багам).

**Лид направления** (Tech Lead) — декомпозиция эпика на атомарные задачи
с JSON-схемой, скоупами и контрактами. Четыре направления: backend,
frontend, devops, qa.

**Специалист** — backend/frontend-разработчик, DevOps-инженер, QA-инженер.
Выполняет одну задачу, сам себя проверяет сборкой, закрывает задачу.

**Приёмка (акцептор)** — детерминированный пайплайн без LLM: установка
зависимостей, сборка, форматирование, анализ, LSP, запуск, чтение логов.

**Чат-ассистент** — агент, обслуживающий чат Web UI: понимает намерения по
смыслу, отвечает по проекту, создаёт эпики, задаёт вопросы.

**Gate** — запрос решения пользователя на действии, которое агент считает
рискованным (деструктивная операция). В UI это баннер с кнопками.

## RAG и контекст

**Чанк** — фрагмент кода, единица индексации. Не более 100 строк
(`rag/chunk.go:21`).

**chunk_id** — идентификатор чанка, производный от (проект, файл, ключ
чанка). Ключ — символ определения, а при линейной нарезке — `L<start_line>`.
Один `chunk_id` делится версиями одной функции между коммитами и ветками.

**Ранг поколения** — версия чанка для конкретной ветки и коммита. Payload
Qdrant хранит `branch`, `commit_sha`, `content_hash`, `replaced_by`; старые
поколения помечаются `replaced_by`, а совсем старые удаляются
(`pruneSuperseded` держит одно предыдущее).

**CodeSearch** — инструмент семантического поиска по коду через Qdrant.

**Эпизод вытеснения** — запись выброшенной части диалога в RAG, чтобы её
можно было найти позже (Ф-7 сжатия контекста).

**Скелетон** — сигнатуры функций и типов без тел; кеш, экономящий чтение
больших файлов (`tools/skeleton.go`).

## Код и проверки

**LSP** — Language Server Protocol. Даёт агенту «взгляд IDE»: диагностики,
переходы к определению, поиск ссылок, hover-документация.

**Step Gate** — проверка по LSP строго изменённых шагом файлов. Есть
ошибка — шаг падает, скоуп откатывается.

**Диагностика** — сообщение LSP об ошибке или предупреждении
(`файл:строка:колонка: текст`).

**Sandbox** — контейнер для команд `Run`. По умолчанию выключен, команды
идут на хост.

**Stub-healing** — автосоздание родительских каталогов и лечение
0-байтовых файлов-заглушек, оказавшихся на пути каталога.

**Инфра-зеркало** — выполнение make-цели `infra.<цель>` через
`docker compose run`, когда на хосте нет нужного инструмента.

## Модели и провайдеры

**Провайдер** — адаптер LLM: Ollama, YandexGPT, Trim.

**LayeredProvider** — двухуровневая маршрутизация: лёгкая модель для
рядовых шагов, тяжёлая (`OLLAMA_MODEL_LARGE`) для лидов, архитектора,
ревьюера и эскалаций при ошибке.

**Тяжёлый шаг** — эвристика: роль лида либо эскалация после ошибки/короткого
ответа.

**Thinking (рассуждение)** — цепочка рассуждения у reasoning-моделей.
Удваивает время и токены на каждом раунде инструментов; часто выгоднее
выключить (`OLLAMA_THINK=0`).

**num_ctx** — окно контекста модели. Меньше окна → 400
`exceeded_context_size` на разросшейся истории.

**Гейт (gate) в ревью** — пауза цикла ревью с вопросом пользователю.

## Git

**Релизная ветка** — ветка эпика `ai/epic/<id>`, в которую сливаются все его
задачи.

**Фича-ветка** — ветка задачи `ai/task/<id>`, база — релизная ветка эпика.

**Worktree** — отдельное рабочее дерево git для задачи. Задача выполняется
в нём и снимается после merge.

**Auto-resolve main sync** — фоновая синхронизация эпика с `main` при
выпуске (таймаут 5 минут).

**Конфликтные файлы** — `merge_conflict_files` на эпике/задаче: список
файлов, которые не удалось смерджить автоматически. Пока поле не пусто,
состояние считается конфликтным.

## Служебное

**Событие (runevent)** — запись о событии агентского цикла: сообщение,
`message_delta`, начало/результат инструмента, расход токенов. Идёт в UI
через WebSocket.

**Scoped-токены** — учёт расхода токенов по скоупам `task:`, `epic:`,
`architecture`, `bugs`, чтобы видеть стоимость по уровням.

**`temp/`** — рабочее хранилище сгенерированных проектов
(`temp/<имя_проекта>/`). Не коммитится, не редактируется вручную, агент
не выходит за его пределы.
