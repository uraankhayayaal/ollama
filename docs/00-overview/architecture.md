## Агентский цикл (`runner/`)

Центральный цикл — `runner.Runner`. Один раунд:

1. Собрать сообщения диалога (системный промпт + задача + история).
2. При необходимости **сжать историю** под бюджет символов/токенов.
3. Вызвать провайдера (`Chat` или `ChatStream`).
4. Разобрать ответ: если модель вернула вызовы инструментов — выполнить их,
   записать результаты в историю, повторить раунд.
5. Если ответ финальный — вернуть результат.
6. Обновить счётчик фактического входа (`lastInputTokens`) — он нужен для
   бюджета следующего сжатия (Ф-11).

Ключевые файлы:

| Файл | Роль |
|---|---|
| `runner/runner.go` | Сам цикл, `ModelLimits`, оценка токенов |
| `runner/compress.go` | Сжатие истории под символьный/токенный бюджет |
| `runner/compression.go` | Ф-6…Ф-11 (памятка, вытеснение, ранжирование, оглавления, компакция) |
| `runner/reindex.go` | Авто-переиндексация RAG после мутаций |
| `runner/autofix.go` | Авто-починка кода по LSP-диагностикам |
| `runner/applog.go` | Автоподмешивание логов приложения в промпт |
| `runctx/` | Сборка сервисов сжатия для CLI/планировщика/сервера |
| `runevents/` | События цикла для UI в реальном времени |
| `runmetrics/` | Реестр метрик и Prometheus-экспорт |

Подробнее — [Сжатие контекста](../20-features/context-compression.md) и
[Токены и метрики](../20-features/tokens-and-metrics.md).

## Инструменты (`tools/`)

Инструменты — function calling: модель возвращает JSON-вызов, раннер
диспетчеризует его по имени.

- **Реестр** — `tools/registry.go`, фабрика `newTool` по имени. Набор
  инструментов агента собирается через `tools.Select(names, deps)`.
- **Зависимости** (`tools.Deps`) — общий контекст: `FileOps`, `Session`
  (ревью), `Board`, `RAG`, `GitExec`. Если `Board == nil`, инструменты
  `Board*` **не выдаются вообще** — агент деградирует до файловых.
- **Серверные мосты** — `server` не может объявить свои инструменты в реестре
  `tools` (цикл импортов), поэтому добавляет их через `Set.Add`:
  `AskUser`, `IndexBackground`, `KanbanStart`, `TaskMerge`, `EpicRelease`,
  `BranchReject`, `ResolveGitConflicts`-обвязка.

Полный список — [Инструменты агентов](../30-reference/agent-tools.md).

## Хранилища

| Что | Где | Пакет | Зачем |
|---|---|---|---|
| Kanban-доска | Redis, `BOARD_REDIS_ADDR` | `board/` | Эпики, задачи, багрепорты |
| Чекпоинты плана | Redis, `REDIS_ADDR` | `checkpoint/` | Статусы шагов для `--resume` |
| История и события чата | Redis Streams | `chat/` | Живой чат в Web UI |
| RAG-индекс | Qdrant, `QDRANT_ADDR` (gRPC) | `rag/` | Семантический поиск по коду |
| Реестр проектов | Файл `$AI_WORKSPACES` | `workspace/` | Имя проекта → путь, git-метаданные |
| Логи | Файлы в `LOG_DIR` | `logging/` | Лог каждого проекта и процесса |
| Проекты агентов | `temp/<имя>/` | `projects/` | Рабочее хранилище (не коммитится) |

`checkpoint` намеренно не зависит от типов planner: снимок хранит `PlanJSON`
как непрозрачные байты (`checkpoint/checkpoint.go:3-7`). Это позволяет менять
структуру плана, не ломая старые чекпоинты.

## Git-изоляция

Агенты не работают в общей ветке:

- **Эпик = релизная ветка** `ai/epic/<id>`.
- **Задача = фича-ветка** `ai/task/<id>`, база — ветка эпика.
- Задача выполняется в **worktree**; при переходе в `done` работает
  `autoCommitAndMergeTask`: коммит → авто-MR → merge в релизную ветку →
  снятие worktree.
- При конфликте — попытка LLM-авторезолва, иначе поле
  `merge_conflict_files` и откат статуса в `in_progress`.

Подробнее — [Git-flow](../20-features/gitops-workflow.md).

## Web-контур

`go run . serve` поднимает один процесс на много проектов:

- **REST** — CRUD доски, чат, git-операции, метрики (`server/server.go:169-248`).
- **WebSocket** — `/api/projects/{id}/ws`: события `chat`, `chat_delta`,
  `board`, `gate`, `tool`, `status`, `log`, `applog`, `tokens`, `chat_clear`.
- **Сессия** — `server/session.go`: оркестрация, AskUser-вопросы, фоновая
  индексация, рассылка снимков при подключении.
- **Фронтенд** — `web/`, сборка `tsc -b && vite build` в `web/dist`,
  встраивается через `//go:embed all:dist` (`web/webui.go:10-20`).

Подробнее — [Web UI](../20-features/web-ui.md),
[REST API и WebSocket](../30-reference/rest-api.md).

## Стабильность и деградация

Система спроектирована так, чтобы внешние зависимости не были обязательными:

| Зависимость недоступна | Поведение |
|---|---|
| Qdrant | Поиск `CodeSearch` возвращает `skipped` с подсказкой; фоновая индексация — `503`; агент работает без RAG |
| Redis (доска) | `kanban` не запускается; standalone-команды (`backend`, `plan`) работают, инструменты `Board*` не выдаются |
| Redis (чекпоинты) | `plan` работает без resume |
| Docker (песочница) | `CODEGEN_SANDBOX=auto` — переход на хост с пометкой `sandbox_note`; `=container` — явная ошибка конфигурации |
| LSP-сервер | `LspCheck` возвращает `skipped`; step-gate молча не срабатывает |
| Команда `make` | Фолбэк `make infra.<цель>`, затем автодетект по стеку |
