# План: диффы веток из задач и эпиков

Статус: **WIP** (реализация завершена; ожидает ручной проверки в Web UI на
проекте пользователя).

## Цель

Убрать устаревшую плавающую кнопку «Дифф» проекта. Она показывает изменения
рабочей копии основного клона, тогда как код задач и эпиков теперь живёт в
отдельных ветках и worktree. Просмотр диффа должен начинаться из самой задачи
или эпика и показывать изменения именно её ветки относительно основной ветки
(`git_base`, обычно `main`). Для отображения и просмотра файлов переиспользовать
существующую компоненту `Diffboard`, при необходимости адаптировав её под
контекстный режим.

## Текущее состояние

- `web/src/App.tsx`: плавающая кнопка «Дифф» открывает проектный `Diffboard`;
  `Diffboard` всегда запрашивает `projectDiff(project)` без ref.
- `web/src/Components/Dashboard/TaskModal/TaskModal.tsx` и
  `EpicModal/EpicModal.tsx`: уже показывают git-сведения через `GitBlock`, здесь
  естественное место для кнопки диффа конкретной ветки.
- `web/src/Components/Diffboard/Diffboard.tsx`: компонент умеет список файлов,
  фильтры и ленивую загрузку side-by-side патчей, но сейчас привязан к
  проектному diff и проектным действиям accept/reject.
- `server/diff.go`: существующий маршрут диффа обслуживает рабочую копию
  проекта; параметры выбора ветки ещё не поддержаны.
- `docs/PLAN-2026-09-23-todo-diffboard-branch.md`: предыдущий план предлагал
  глобальный Diffboard с селектором веток. Этот план меняет точку входа на
  контекстные кнопки в модалках задач и эпиков. Повторно использовать из него
  полезные серверные решения: ref/vs, worktree задачи, merge-base/three-dot и
  исправление кэша. Этап «Все изменения» и селектор проекта не входят в эту
  задачу.

## Поведение

1. Удалить плавающую кнопку «Дифф» проекта. Кнопка «Логи» остаётся на месте.
2. В `GitBlock` модалки эпика показывать «Дифф» для ветки эпика; в `GitBlock`
   модалки задачи — «Дифф» для ветки задачи. Не показывать кнопку, если нужная
   ветка ещё не создана или проект не git-типа.
3. Нажатие открывает общий `Diffboard` в контексте выбранного ref и показывает
   изменения этой ветки относительно основной ветки проекта (`git_base`). Для
   задачи включать незакоммиченные изменения её worktree, если worktree есть.
4. Использовать имеющиеся в `Diffboard` фильтрацию файлов и side-by-side
   просмотр. В заголовке явно показать имя/тип сущности, source branch и
   основную ветку сравнения.
5. Закрытие Diffboard возвращает к той же открытой модалке. Открытие другого
   diff сбрасывает раскрытые файлы, фильтры, патчи и ошибки предыдущего ref.
6. Контекстный режим — только просмотр. Кнопки «Принять»/«Отклонить» текущего
   проектного diff не показывать для веток задач и эпиков; существующие
   проектные действия не должны случайно применяться к выбранному ref.
7. Если у ветки пока нет изменений, показать понятное пустое состояние. Ошибки
   отсутствующей ветки/worktree должны объяснять причину, не скрывать дифф другой
   ветки и не превращаться в пустой успешный результат.

## Решения реализации

### Серверный API

Расширить существующий `GET /api/projects/{id}/diff` параметрами `ref` и `vs`,
сохранив прежнее поведение при их отсутствии. Для контекстного запроса передавать
`ref=ai/epic/<id>` или `ref=ai/task/<id>`, `vs=<git_base>`.

- Ветка задачи с зарегистрированным worktree: получить коммитный diff от merge
  base до HEAD и включить незакоммиченные правки worktree.
- Эпик и задача без worktree: получить трёхточечный diff коммитов
  `vs...ref` из основного клона.
- Проверять ref по реестру веток проекта; не принимать произвольные пути,
  переданные клиентом.
- Ленивый запрос файла (`?file=`) должен использовать тот же ref/vs, что и
  запрос списка файлов.
- Исправить/расширить кэш: отдельный ключ на проект/ref/vs; список файлов
  обновляется на запрос списка, а патчи относятся только к соответствующему
  diff. Инвалидировать данные при изменениях веток, merge/release/reject.
- Текущий API без ref остаётся совместимым для иных клиентов, но Web UI больше
  не предлагает глобальный просмотр проектной рабочей копии.

### Web UI и Diffboard

- Добавить ref/vs в `projectDiff` и `projectDiffFile`.
- Передать в `GitBlock` callback открытия диффа с типом сущности, ID и branch.
- Поднять состояние выбранного diff выше модалок так, чтобы `Diffboard` мог
  открыться поверх Dashboard и закрыться обратно к исходной модалке.
- Сделать `Diffboard` контекстной панелью: заголовок выбранной сущности,
  правильные API-параметры, без проектных accept/reject-действий; сбрасывать
  локальное состояние при смене ref.
- Удалить `showDiffboard`-FAB, его условие отображения и неиспользуемую
  связующую логику. Структуру `diff-drawer` сохранить или упростить, не затронув
  Logboard.
- Сделать панель пригодной для небольших модалок/экранов: понятная кнопка
  закрытия, заголовок с контекстом, адаптивная высота и прокрутка.

### Выполнено в этой реализации

- REST принимает `ref`/`vs`, разрешает ref только по side-реестру проекта и
  включает незакоммиченные файлы task worktree; патчи загружаются из кэша ключа
  `(project, ref, vs)`. Кэш сбрасывается при создании/удалении worktree,
  создании веток, merge/release и существующих reject/accept действиях.
- GitBlock показывает кнопки для созданных веток эпиков и задач. Общая
  Diffboard открывается над модалкой, показывает сущность и сравнение с базовой
  веткой; смена ref очищает состояние, а Escape закрывает только Diffboard.
- Добавлен интеграционный серверный тест на настоящем локальном Git-репозитории:
  эпиковый коммит и незакоммиченный файл task worktree видны в diff относительно
  `main`.
- `go build` и `go vet` по перечню пакетов из AGENTS.md прошли. Полный `go test`
  выполнен, но падают `TestChatAssistantDeleteTaskAfterConfirm`,
  `TestChatAssistantPublishesBoardWhenIdle` и `TestChatAssistantCreatesBugAndTask`.
