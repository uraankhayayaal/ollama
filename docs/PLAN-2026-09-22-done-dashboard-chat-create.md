# План: Создание эпиков и задач через чат — сводка обязательных параметров

Статус: **РЕАЛИЗОВАН**. Формат — как в `PLAN-2026-09-17-done-webui.md` / `PLAN-2026-09-19-done-lsp.md`.
Закрывает TODO из `PLAN-dashboard-gitflow.md` (строки 11–17).

## Цель

Чтобы ассистент в чате, создавая **эпик** или **задачу**, всегда собирал у
пользователя **сводку обязательных параметров**, не угадывал критичные поля и
не создавал мусор на доске. Должны быть покрыты минимум-параметры:

- **Эпик**: требуется ли ревью архитектора; если нет — известно ли, к какому
  лиду эпик (инфраструктура/бэкенд/фронтенд/QA) относится; «спросить у
  пользователя» — допустимая стратегия при неоднозначности. Также прочие
  обязательные поля (title, description, assigned_role).
- **Задача**: создаётся в рамках конкретного эпика (из контекста разговора
  определяется автоматически; при неоднозначности — «спросить у пользователя»);
  назначение специалисту (из контекста; если задача затрагивает разных
  специалистов — лучше оформить как эпик → через архитектора); прочие
  обязательные поля.

Проблемы: модель часто угадывает `assigned_role`/эпик, не уточняет «какой лид»
и «нужно ли ревью архитектора», молча заполняет поля.

## Решения

1. **Расширить `assistantSystemPrompt`** чек-листами обязательных параметров
   эпика и задачи + явной стратегией: при неоднозначности — **«спроси
   пользователя»** (не угадывать, не создавать, пока не собрана сводка).
2. **Зафиксировать «сводку» как обязательный шаг перед созданием:** перед
   `BoardCreateEpic`/`BoardCreateTask` ассистент обязан (a) собрать все поля,
   (b) при неоднозначности — задать уточняющие вопросы пользователю,
   (c) ВЫВЕСТИ собранную сводку в чат перед вызовом инструмента. В промпте —
   пример сводки.
3. **Семантические правила:**
   - Эпик: если ревью архитектора не требуется → обязательно определить лида
     (инфраструктура/бэкенд/фронтенд/QA); иначе — «спросить».
   - Задача: эпик определяется автоматически из контекста (текущий эпик в
     обсуждении), при сомнении — «спросить»; задача, затрагивающая разные
     направления, не создаётся как задача — ассистент предлагает перевести в
     эпик (архитектор раздаст лидам); назначение специалисту — из контекста.
4. **Опционально:** добавить в схему `BoardCreateEpic` поле
   `architect_review: bool` («требуется ли ревью архитектора») и пояснение в
   описании `assigned_role`; в `BoardCreateTask` аналогично пояснить про эпик.
   Это делает «сводку» проверяемой на стороне инструмента (низкий приоритет:
   изменение схемы влияет на модели всех агентов — с осторожностью).
