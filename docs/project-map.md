# Карта проекта: AI-агенты генерации кода

Это документация в виде «карты»: назначение, структура папок, фичи,
переменные окружения, ключевые особенности и текущий TODO.

Код написан на Go (`module ai`, `go 1.26.5`). Промпты, комментарии и логи —
на русском. Зависимости: `github.com/ollama/ollama`, `openai-go`,
`go-redis/v9`, `miniredis/v2`, `godotenv`.

> **В работе:** Web UI-оболочка «Доска + Чат + Дифф» с полным HITL —
> см. [PLAN-webui.md](PLAN-webui.md).

---

## 1. Что это

Мультиагентная система автоматической разработки. По промпту пользователя
агенты проектируют, генерируют, собирают, тестируют и ревьюируют приложения,
работают с Kanban-доской и ревьюят Merge Request'ы.

Команды (точка входа `main.go`):

| Команда | Что делает |
|---|---|
| `go run . backend <имя> [промпт]` | Backend-разработчик: генерирует серверный код |
| `go run . frontend <имя> [промпт]` | Frontend-разработчик: генерирует клиентский код |
| `go run . plan <имя> <промпт> [--resume]` | Планировщик: план + исполнитель шагов по волнам |
| `go run . kanban <имя> <промпт>` | Оркестрация: Архитектор → лиды → специалисты через Redis-доску |
| `go run . backendlead / frontendlead / devopslead / qalead <имя> <промпт>` | Лиды: декомпозиция на JSON-задачи |
| `go run . devops <имя> <промпт>` | DevOps-инженер: Docker/K8s/CI-CD |
| `go run . qa <имя> <промпт>` | QA-инженер: автотесты по контрактам, баг-репорты |
| `go run . review <URL>` | Код-ревью Merge Request'а (GitLab/GitHub) |
| `go run . accept <имя_проекта>` | Приёмка собранного приложения (без LLM, детерминированно) |
| `go run . listen` | Слушатель новых MR в GitLab-проектах |

> `generate` — устаревший алиас для `backend`.

## 3. Список фичей

### Агенты и роли
- **Backend/Frontend-разработчики** — генерация проекта за один ответ (весь
  код одним `WriteFiles`-раундом, большой токен-бюджет).
- **Четыре Tech Lead** (backend, frontend, devops, QA) — верхнеуровневое
  проектирование и декомпозиция в строгий JSON по схеме задания.
- **Системный архитектор** — публикует эпики на Redis-доску Kanban.
- **DevOps-инженер** — Docker Compose, Kubernetes, CI/CD, проверка командами.
- **QA-инженер** — автотесты по контрактам, единая команда запуска, баг-репорты.
- **Код-ревью MR** — критические замечания, блокировка апрува, ревью по частям.

### Планировщик и исполнение
- `run . plan` — построение плана и **исполнение шагов волнами параллельности**
  (`CODEGEN_PARALLEL`); независимые шаги выполняются одновременно.
- **Scoped-снимки** перед каждым шагом — изолированный откат по неудачному шагу
  (`CODEGEN_ROLLBACK_ON_FAIL`), откат только к предыдущему состоянию.
- **Приёмка в цикле** (`ACCEPT_MAX_ROUNDS`): сборка → запуск → логи →
  при неудаче планировщик строит шаги исправления (багфикс-цикл).
- **Аудит публичных API** (`tools/contract.go`): снимок Go-API после каждого
  шага и его diff (`+/-/~`), `CODEGEN_CONTRACT_ENFORCE` для строгого режима.
- **Аудит изменений файлов**: `Snap.Diff()` → дайджест (создано/изменено/удалено)
  с учётом scope и exclude.
- **Чекпоинты в Redis**: статусы шагов, resume через `--resume`/`PLAN_RESUME`,
  метрики шага (`TrackMetric`) в снимке чекпоинта.

### LLM-провайдеры и маршрутизация
- **LayeredProvider** — две модели: малая для быстрых шагов, большая
  (`OLLAMA_MODEL_LARGE`) для лидов/ревью и эскалаций при ошибках
  (`LLM_ALWAYS_HEAVY` — всё на большой).
- **OLLAMA_THINK** — принудительное вкл/выкл цепочки рассуждения у
  reasoning-моделей (qwen3 и др.).
- Провайдеры: **Ollama**, **YandexGPT** (Alisa), **Trim** (`noChunk` — дифф
  ревью передаётся целиком, без разбиения).

### История и контекст
- **Скелетон-кеш** (`tools/skeleton.go`) — кэш структуры проекта по
  `path|size|mtime`, кап 512, очистка при переполнении.
- **Сжатие истории** (`runner/compress.go`) — под символьный бюджет
  `CODEGEN_HISTORY_BUDGET`: начало (system + задача) + хвост диалога, разрыв
  внутри tool-сообщений запрещён.
- **Resume-состояние** агентного цикла в чекпоинте (продолжение прерванного шага).

### Приёмка кода
- Приёмка **без LLM** (детерминированно): установка зависимостей, сборка,
  запуск, контроль логов за таймаут, автодетект Go/Node/Python и
  **монорепозиториев** (по подпроектам `frontend/`, `server/`).
- Проверки `gofmt`/`vet` (эквиваленты prettier/black и eslint/ruff для других
  стеков): формат — предупреждение, анализ — ошибка (reject).

### Инфраструктура и устойчивость
- **Stub-healing**: если «каталог» оказался 0-байтовым файлом-заглушкой,
  инструменты файловых операций автоматически лечат путь (создают каталог);
  непустой файл на пути — ошибка, не трогается.
- **listen** (`services/mrlistener`) — периодический мониторинг новых MR
  (`POLL_INTERVAL`), база известных MR в файле.
- Прочее: лимиты чтения файлов, ограничение таймаутов команд `Run`,
  `CODEGEN_NO_OVERWRITE` по ролям, русскоязычные промпты.

## 5. Особенности и ключевые решения

- **Весь проект одним ответом.** Промпты требуют завершать задачу в одном
  ответе с единым `WriteFiles`: меньше раундов, меньше потерь контекста.
  Для Yandex бюджет токенов на первом раунде увеличивается до 16 000.
- **Волны и scoped-снимки.** Шаги плана разрезаются на волны независимости;
  перед каждым шагом снимается «scope»-снимок (только затронутые каталоги),
  что позволяет откатывать именно неудачный шаг, не затрагивая соседние.
  Файловые мутации при этом сериализуются пер-проектной блокировкой
  (`tools/filelock.go`): параллельные шаги одной волны не рвут общие файлы.
- **Двухслойная маршрутизация.** Лиды, ревьюер и эскалации идут на
  `OLLAMA_MODEL_LARGE` (высокое качество), рядовые шаги — на `OLLAMA_MODEL`.
  Эвристика: «тяжёлый» тип = роль лида + эскалация при ошибке/коротком ответе.
- **Thinking-модели.** `OLLAMA_THINK` управляет цепочкой рассуждения: она
  удваивает время и токены на каждом раунде инструментов — часто выгоднее
  отключить.
- **Контракты публичного API.** Планировщик парсит Go-код и снимает снимок
  публичного API между шагами; любое необъявленное изменение (поломка
  контракта) видно в журнале аудита. Пока реализовано для Go.
- **Приёмка — без LLM.** Агент-приёмка детерминирован: установка зависимостей,
  сборка, запуск, проверка логов; монорепозитории принимаются по подпроектам.
  Именно это защищает деплой от «красивых, но не собирающихся» проектов.
- **Stub-healing.** Каталоги не создаются «по месту» агентами напрямую —
  файловые инструменты сами создают родительские каталоги и лечат 0-байтовые
  файлы-заглушки на пути (см. `tools/fileops.go`).
- **Скелетон-кеш и сжатие истории** защищают контекст на длинных сессиях
  (десятки раундов инструментов).
- **Детерминированные проверки** gofmt/vet (аналог prettier/black и
  eslint/ruff) подключаются в приёмке и к каскадным оценкам качества.
- **Ecosystem Redis**: чекпоинты плана, Kanban-доска, метрики шагов поднимаются
  `docker compose up -d` (`compose.yaml`).
- **`temp/` не коммитится.** Генерируемые проекты — артефакты агентов; единый
  путь `temp/<имя_проекта>/` задаётся в `projects.ProjectDir`.
- **Русский язык** во всех промптах/логах; `readme.md` содержит инструкции для
  локального запуска (Apple Silicon) и работы с несколькими `.env.macbook.*`.
