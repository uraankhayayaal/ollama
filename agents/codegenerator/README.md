# Агент-генератор кода

Агент `codegenerator` по текстовому заданию пишет целый проект (Go по
умолчанию) в новый каталог `temp/gen_<дата>_<время>_<номер>/`, сам проверяет,
что код собирается, а затем дополнительно прогоняет его через агента
кодревью и исправляет найденные проблемы.

```bash
go run . generate "Напиши микросервис для расчёта квадратного уравнения и формат аргументов запуска."
```

Первым аргументом передаётся задание; если оно пустое — используется
задание по умолчанию.

В конце цикла в OutputDir всегда появляется `README.md` с инструкцией по
установке, запуску и использованию, собранной из реально созданных файлов
(модуль, версия Go, точка входа, наличие тестов). Если модель уже написала
свой `README.md` — сгенерированный не перезапишет его.

---

## Инструменты

Агент работает через набор инструментов (доступны и в OpenAI/Yandex,
и в Ollama):

| Инструмент      | Описание                                                        |
|-----------------|-----------------------------------------------------------------|
| `WriteFile`     | Запись одного файла                                             |
| `WriteFiles`    | Пакетная запись нескольких файлов (структура проекта)           |
| `ReadFiles`     | Чтение содержимого файлов (для итеративной разработки)          |
| `DeleteFiles`   | Удаление файлов или папок                                       |
| `Run`           | Запуск команд в OutputDir (go build / go vet / go test)         |

Все операции ограничены директорией вывода: пути с `..` или абсолютные пути
отклоняются (защита от записи вне OutputDir).

## Реализованные фичи

### 1. Безопасные пути в пределах OutputDir
Все инструменты (`WriteFile`, `WriteFiles`, `ReadFiles`, `DeleteFiles`) пишут
только внутрь OutputDir. Попытка выйти за пределы (`../`, абсолютный путь)
отклоняется с ошибкой. `WriteFile` и `WriteFiles` пишут в одно и то же место
(ранее `WriteFile` ошибочно писал относительно рабочей директории).

### 2. Полный набор инструментов для всех провайдеров
Раньше `ReadFiles`/`DeleteFiles` были доступны только для Ollama. Теперь они
зарегистрированы и в `GetTools` (OpenAI/Yandex), и в `GetToolsForOllama`
(Ollama), и в `CallFunction`.

### 3. Инструмент `Run` и самопроверка кода
После записи агент сам запускает `go build ./...`, `go vet ./...`,
`go test ./...` через инструмент `Run` и возвращает вывод ошибок модели.
Модель исправляет код, пока сборка не станет «зелёной».

### 4. Self-review (цикл repair)
После первой генерации код прогоняется через логику кодревьюера в локальном
режиме (без сети, `forges.LocalForge`): строится дифф по файлам директории,
а комментарии собираются в памяти. Найденные замечания передаются модели,
которая исправляет код в той же OutputDir, после чего записывается отчёт.

### 5. Мета-отчёт `SUMMARY.md`
После завершения цикла в OutputDir пишется `SUMMARY.md` со структурой
сгенерированного проекта (язык, задание, список файлов).

### 6. Гарантированный `README.md`
В конце OutputDir всегда появляется `README.md` с инструкцией по установке,
запуску и использованию, собранной из реально созданных файлов (модуль,
версия Go из `go.mod`, точка входа, наличие тестов). Если модель уже написала
свой `README.md` — он не перезаписывается.

### 7. Защита от перезаписи и лимит файлов
- `CODEGEN_NO_OVERWRITE=true` — инструменты не перезаписывают существующие файлы.
- `CODEGEN_MAX_FILES` — ограничение числа файлов за запуск.

### 8. Гибкая конфигурация через окружение
Целевой язык, имя модуля Go, лимиты и отчёт задаются переменными
`CODEGEN_*` (см. `.env.example`).

---

## Настройки (переменные окружения)

| Переменная               | По умолчанию      | Назначение                                  |
|--------------------------|-------------------|---------------------------------------------|
| `CODEGEN_LANG`           | `Go`              | Целевой язык программирования               |
| `CODEGEN_MODULE`         | (пусто)           | Имя модуля Go для `go.mod`                  |
| `CODEGEN_MAX_FILES`      | `0`               | Максимум файлов за запуск (0 — без лимита)  |
| `CODEGEN_NO_OVERWRITE`   | `false`           | Запрет перезаписи существующих файлов       |
| `CODEGEN_SUMMARY_FILE`   | `SUMMARY.md`      | Имя файла-отчёта (пусто — отключить)        |

---

## Идеи на будущее

- **Поддержка нескольких языков/пакетных менеджеров** в инструменте `Run`
  (npm, pip, maven и т.п.) кроме Go.
- **План перед кодом** — агент сначала отдаёт структуру/план файлов,
  пользователь подтверждает, потом пишет.
- **Несколько раундов repair** (не один) с фиксированным бюджетом, пока
  число замечаний не станет нулевым.
- **Защита от перезаписи поверх нескольких списков** и вывод сравнения
  «стало/было» для изменённых файлов.
- **Очистка старых `temp/gen_*`** — автоподчистка по возрасту/размеру.
